# THE HOUSE — Development roadmap

## Milestone 0 — Prototype foundation
- [x] Godot project and main scene
- [x] First-person movement and flashlight
- [x] Main menu, settings and pause menu
- [x] Automated Windows x64 export workflow
- [ ] Validate the latest environment build in Godot and on Windows

## Milestone 1 — Expanded environment prototype
- [x] Replace single-room greybox with a multi-room mansion layout
- [x] Add foyer, salon, dining room, kitchen, library and bedroom spaces
- [x] Add procedural furniture, windows, bookcases, props and room lighting
- [ ] Add true stairwell traversal and a fully connected basement
- [ ] Add authored material texture sets and detailed mesh assets
- [ ] Verify collision and navigation throughout the complete floor plan

## Milestone 2 — Core playable loop
- [ ] Inventory and item inspection
- [ ] Keys, locked doors and item dependencies
- [ ] At least three interconnected environmental puzzles
- [ ] Hiding spots and reliable enemy search behaviour
- [ ] Death, retry and checkpoint flow
- [ ] First complete 20–30 minute playable chapter

## Milestone 3 — Production art and audio
- [ ] Original monster model, rig and animation set
- [ ] Detailed authored environment meshes
- [ ] PBR albedo, normal, roughness and metalness texture sets
- [ ] Lighting, shadows and post-processing pass
- [ ] Original ambience, footsteps, creature audio and interaction sounds
- [ ] Performance profiling at 1080p

## Milestone 4 — Story campaign
- [ ] Finalize protagonist, motivation and central mystery
- [ ] Write the full 4–5 hour first-playthrough story
- [ ] Implement notes, recordings and scripted story events
- [ ] Build critical path, optional discoveries and multiple endings
- [ ] Balance an expert speedrun route targeting approximately one hour

## Milestone 5 — Release preparation
- [ ] Save/load and settings persistence
- [ ] Difficulty and accessibility options
- [ ] Full campaign playtest from a clean save
- [ ] Windows x64 export and clean-machine verification
- [ ] Bug fixing and performance pass

## Acceptance rule

A task is complete only after it is implemented and verified in-engine. A successful executable export proves packaging, not visual quality, playability or campaign completeness. Never mark a milestone complete based only on source code existing.
